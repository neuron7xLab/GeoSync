## 2. Core thesis

GeoSync becomes high-rank only if every predictive claim is bound to measured artifacts.

A valid inference path must satisfy:

```text
contextualize -> generate -> compute -> integrate -> falsify -> recurse -> narrow claim -> preserve evidence -> promote rank
```

The system must never promote a claim because the idea sounds advanced. Ricci curvature, Kuramoto synchronization, manifold dynamics, and market microstructure are only valid when connected to deterministic data contracts, explicit estimators, reproducible outputs, and failed-null evidence.

### 2.1 Generative operator

Definition:

To generate is to sample a new candidate point from the learned or specified distribution of possible outputs, using the absorbed structure of prior data, constraints, and theory without copying the input.

Canonical form:

```text
context + constraints + learned_distribution -> candidate_output -> validation_target
```

Generation is valid only when the produced candidate becomes an object of measurement. A generated hypothesis, kernel variant, feature, graph rule, phase extractor, or claim has no scientific status until it is converted into a typed artifact and challenged by replay, nulls, baselines, and residual analysis.

Required generative invariants:

1. Generation must declare its source distribution or rule family.
2. The candidate must be typed, serializable, hashable, and replayable.
3. The candidate must not be treated as evidence before validation.
4. Copying an input is not generation; uncontrolled novelty is not science.
5. Every generated candidate must enter the falsification queue.
6. Failed generated candidates are retained as negative evidence, not hidden.
7. A generator is promoted only if its candidates repeatedly improve evidence quality under fixed validation.

Acceptance gate:

A generated output is admissible only if it emits a candidate artifact with a contract, provenance, validation plan, expected failure modes, and an explicit claim-tier ceiling.

### 2.2 Integration operator

Definition:

To integrate is to connect independent computational streams so that the output of one becomes a typed and validated input of another, producing a fused evidence-state that no module could reach alone.

Canonical form:

```text
stream_A.output -> contract_A_to_B -> stream_B.input -> fused_state -> evidence_artifact
```

Integration is valid only when composition increases evidence quality, failure localization, predictive stability, or reproducibility. Placing modules in the same repository is not integration. Integration requires contracts, deterministic data transfer, replayable fusion, and comparison against standalone modules.

Required integration invariants:

1. Each stream has a declared typed output contract.
2. Each downstream module has a declared input contract.
3. Cross-stream transfer is deterministic, hashable, and replayable.
4. Fused output is compared against every standalone module.
5. Fusion is compared against randomized/null fusion baselines.
6. If the fused state does not improve evidence quality or failure localization, the integration claim is downgraded.

GeoSync integration chain:

```text
L2 tensor -> manifold graph -> Ricci field
L2 tensor -> oscillator extraction -> Kuramoto phase field
Ricci + Kuramoto + liquidity -> fused fragility kernel -> validation suite -> claim card
```

Acceptance gate:

An integrated state is valid only if it produces a fused artifact whose evidence value exceeds standalone Ricci, standalone Kuramoto, naive microstructure features, and null-fusion controls under the same validation protocol.

### 2.3 Recursive operator

Definition:

To recurse is to run the system output as a new constrained input of the same validation system, forcing the model, kernel, and claim layer to verify their own result through iterative self-refutation until a stable evidence state is reached.

Canonical form:

```text
output_n -> evidence_n -> contradiction search_n -> residual map_n -> revised input_(n+1)
```

Recursion is valid only when the next iteration is stricter than the previous one. The previous answer is not allowed to validate itself. It must become a target for null challenge, residual analysis, replay, perturbation, and claim-boundary reduction.

Required recursive invariants:

1. The previous output is treated as suspect until reproduced.
2. Every iteration must expose at least one measurable residual, failure mode, or stability condition.
3. A claim can only survive recursion by becoming narrower, more evidenced, or more reproducible.
4. No recursion may rewrite frozen artifacts to preserve a claim.
5. Convergence means stable artifact hash, stable metric range, bounded uncertainty, and no unresolved contradiction above threshold.
6. Non-convergent recursion downgrades the claim tier instead of extending the narrative.

Acceptance gate:

A recursive cycle is valid only if it emits one of: reproduced artifact hash, failed claim with cause, narrower claim boundary, stricter validation rule, updated residual-informed kernel input, or promoted claim with evidence pointer.

### WP-09 Recursive falsification loop

Objective:
Run system output as next system input until stability or refutation.

Loop:

```text
kernel output -> evidence artifact -> claim classifier -> null challenge -> residual analysis -> revised context -> next kernel run
```

Recursive procedure:

1. Capture the kernel output and freeze its artifact hash.
2. Convert the output into a new validation input.
3. Generate contradiction probes against the output claim.
4. Run null, baseline, perturbation, replay, and residual checks.
5. Compare the new evidence state against the previous claim boundary.
6. Either reproduce, narrow, demote, or retire the claim.
7. Continue until convergence or stop-rule activation.

Convergence condition:

```text
stable_hash + stable_metric_band + bounded_uncertainty + failed_nulls + no_open_residual_above_threshold
```

Acceptance gate:
Every recursion must produce one of:

- reproduced artifact hash;
- failed claim with cause;
- narrower claim boundary;
- stricter validation rule;
- residual-informed kernel update;
- promoted claim with evidence pointer.

## 7. Stop rules

The work must stop or downgrade claim tier if:

1. Null models match or beat the kernel.
2. Out-of-sample performance collapses.
3. Transaction costs destroy signal utility.
4. Curvature or phase signal is unstable across sessions.
5. Results require hidden manual intervention.
6. Frozen artifacts must be rewritten to preserve a claim.
7. Evidence cannot be reproduced from the bundle.
8. Recursive validation cycles without producing new evidence, a narrower claim, or a reproduced artifact.
9. Generated candidates are promoted before validation.
10. Integrated output fails to beat standalone or null-fusion controls.

A failed claim is not a failed project. A hidden failure is a failed project.
